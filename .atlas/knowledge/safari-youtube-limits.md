# Safari + YouTube platform limits (verified in this project)

| Date | Finding | Evidence | Consequence |
|---|---|---|---|
| 2026-11-03 | Volume booster is impossible in Safari. `AudioContext.createMediaElementSource(video)` connects and reports `state: running`, gain set to 4, source attached, but the audible level does not change. WebKit does not route MSE (Media Source Extensions) audio, which YouTube uses for every stream, through Web Audio. Tested from both the isolated content-script world and the page world (`world: "MAIN"`). | `[ytx] boost {level: 4, result: {level: 4, state: "running", sources: true}}` in the YouTube tab console, Safari 27.2, macOS 27.2, no change in loudness; same result from a hand-written console snippet in the page context. | Feature removed from settings, toolbar and page bridge. Do not reintroduce unless WebKit ships MSE support in `MediaElementAudioSourceNode` (track https://bugs.webkit.org/ for "MediaElementAudioSourceNode MSE"). |
| 2026-11-03 | YouTube's CSP blocks an injected `<script src=safari-web-extension://…>` (`strict-dynamic` + Trusted Types). | Bridge calls timed out until `page.js` became a `world: "MAIN"` content script. | Page-world code must be declared in the manifest, never injected. |
| 2026-11-03 | Ctrl+scroll never reaches the page on macOS Safari; Ctrl+click is the system right-click. | Wheel listener fired for plain and Option scroll only. | Modifier gestures use Option (⌥). |
| 2026-11-03 | After an extension reinstall or update, open YouTube tabs keep the old content script and lose their `storage.onChanged` listener. | New settings "needed a reload" during development. | `background.js` reloads every youtube.com tab on `runtime.onInstalled`. |

## YouTube internals used by the extension (verified from the live bundles, 2026-11-03)

- Full screen on the desktop watch page is requested on `document.documentElement`, not the player: `toggleFullscreen` in base.js takes the `externalFullscreen` branch and calls `ur(window.document.documentElement)`; Shorts and mini-apps do the same. The app then reads `document.fullscreenElement` (`_.xL()`, `Yf()`) on `fullscreenchange` and calls `player.setFauxFullscreen(true)`; no YouTube CSS depends on `:fullscreen`. `winfull.js` therefore spoofs the getters and fires the event instead of restyling elements.
- Captions module (`player_es6.vflset/en_US/captions.js`): `setOption("captions","track", t)` matches `t.languageCode` against the track list (first match wins, manual tracks listed before ASR), and `t.translationLanguage` (an entry of `getOption("captions","translationLanguages")`) makes a translated copy of that track; `tracklist` takes `{ includeAsr: true }`; plain track copies expose `is_translateable`, `vss_id`, `kind` ("asr").
- The 156 translation language codes in `defaults.js` (`LANGS`) come from `translationLanguages` in `ytInitialPlayerResponse`; all resolve in `Intl.DisplayNames`.
- Theme: YouTube serves a different main stylesheet per theme (`/s/_/ytmainappweb/_/ss/...`, selected by the `PREF` cookie `f6=400` for dark) and pins a few colour tokens in it with a `:root:root` rule (specificity above `[dark]`), the Subscribe button text among them. Forcing the `dark` attribute on a page served light therefore leaves that button white on white. Switch themes through YouTube's own action instead: dispatch `yt-action` on `ytd-app` with `actionName: "yt-signal-action-toggle-dark-theme-on" | "-off" | "-device"` (handled by `ytd-app`, which saves the pref and reloads when the theme changes); wait for `yt-navigate-finish` before dispatching.
