# Safari Web Extension (iOS + macOS) platform notes — for a YouTube extension built from the Xcode "Safari Extension App" template

Compiled 2026-11-02. Machine checked: macOS 27.2 (26B123), Safari 27.2, Xcode 27.2 (27B52) at /Applications/Xcode.app, `xcode-select -p` = /Library/Developer/CommandLineTools (so `xcodebuild` fails unless `DEVELOPER_DIR` is set), CLT Swift 6.2.3, Xcode's own toolchain Swift 6.4.2.
Conventions: every bullet carries its source URL. "(local)" = verified by running the command on this machine. "(unverified)" = could not confirm in an official source. MDN compat data = `@mdn/browser-compat-data` 8.1.8 (2026-11-02) read from https://unpkg.com/@mdn/browser-compat-data/data.json (repo: https://github.com/mdn/browser-compat-data).

## 1. Architecture

- A Safari web extension is JavaScript/HTML/CSS packaged as a macOS, iOS or visionOS *app extension* that ships inside a containing app (Mac app, iOS app, visionOS app, or Mac Catalyst app); Xcode packages it; distribution requires the Apple Developer Program. Availability: macOS Safari 14+, iOS 15+, visionOS 1+, Mac web apps macOS 15+. https://developer.apple.com/documentation/safariservices/safari-web-extensions
- Three sandboxed parts: the containing app (may have UI), the web files running in Safari, and a native app extension that mediates between them; app groups share data between app and extension. https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension
- Template: File > New > Project > Multiplatform > "Safari Extension App"; options Product Name, Team, Organization Identifier (reverse DNS, combined into the bundle ID), Language (Swift/Obj-C for the container/messaging code), Include Tests. Generated extension Resources: `_locales`, `images`, `manifest.json`, `background.js`, `content.js`, `popup.html/js/css`. https://developer.apple.com/documentation/safariservices/creating-a-safari-web-extension
- What each template file does (read from Xcode 27.2's own template files under `/Applications/Xcode.app/Contents/Developer/Library/Xcode/Templates/Project Templates/MultiPlatform/Application/SharedContent Safari Extension*.xctemplate`, local):
  - `Shared (Extension)/SafariWebExtensionHandler.swift`: `NSObject, NSExtensionRequestHandling`; `beginRequest(with:)` reads `context.inputItems.first as? NSExtensionItem`, `userInfo[SFExtensionMessageKey]` (iOS 15/macOS 11+), `userInfo[SFExtensionProfileKey]` (iOS 17/macOS 14+), replies with `context.completeRequest(returningItems:[NSExtensionItem], completionHandler:nil)`, echoing `{echo: message}`.
  - `Shared (Extension)/Resources/manifest.json`: `manifest_version: 3`, `default_locale: "en"`, `name/description` via `__MSG_extension_name__`, PNG icons 48/96/128/256/512, `background: {scripts:["background.js"], type:"module"}` (a page, not a service worker), `content_scripts` with `matches:["*://example.com/*"]`, `action: {default_popup, default_icon:"images/toolbar-icon.svg"}`, empty `permissions`.
  - `background.js` (onMessage echo), `content.js` (sends `{greeting:"hello"}`), `popup.html/js/css` (`color-scheme: light dark`, `font-family: system-ui`), `_locales/en/messages.json`, `images/icon-{48,64,96,128,256,512}.png`, `images/toolbar-icon.svg`.
  - `Shared (App)/ViewController.swift`: a `WKWebView` loading `Main.html` + `Script.js` + `Style.css`; on macOS calls `SFSafariExtensionManager.getStateOfSafariExtension(withIdentifier:)` to show on/off state and `SFSafariApplication.showPreferencesForExtension(withIdentifier:)` from an "open-preferences" button; both calls are `#if os(macOS)` only. `extensionBundleIdentifier = "<appBundleID>.Extension"`.
  - `iOS (App)/AppDelegate.swift`, `SceneDelegate.swift`, `Main.storyboard`, `LaunchScreen.storyboard`, `Info.plist`; `macOS (App)/AppDelegate.swift`, `Main.storyboard`, `Info.plist`.
  - `iOS (Extension)/Info.plist` and `macOS (Extension)/Info.plist`: `NSExtension` → `NSExtensionPointIdentifier = com.apple.Safari.web-extension`, `NSExtensionPrincipalClass = $(PRODUCT_MODULE_NAME).SafariWebExtensionHandler` (local, packager-generated project).
- Built layout (local): macOS → `App.app/Contents/PlugIns/App Extension.appex/Contents/Resources/manifest.json` (+ your JS); iOS → `App.app/PlugIns/App Extension.appex/`. Targets: `App (iOS)`, `App (macOS)`, `App Extension (iOS)`, `App Extension (macOS)`; schemes: `App (iOS)`, `App (macOS)`; extension bundle ID defaults to `<app bundle id>.Extension`; both platforms share the same app bundle ID. The Xcode 27 project file is `Project.xcodeproj/project.xcproj` (text, JSON-like), not `project.pbxproj` (local; format not documented in the sources consulted, unverified).
- iOS vs macOS: iOS background page must be non-persistent; iOS lacks some APIs (windows create/remove/update, contextMenus, webRequest per Apple); the containing iOS app cannot send messages to the extension JS (macOS can via `SFSafariApplication.dispatchMessage`). https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility , https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension
- Native messaging: add `"nativeMessaging"` to `permissions`; from background/extension pages (not content scripts) call `browser.runtime.sendNativeMessage("application.id", msg, cb)` — Safari ignores the id and always routes to the containing app's extension; `connectNative` + `port.onMessage` for app→JS on macOS only. https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension
- Promise form `await browser.runtime.sendNativeMessage({...})` is what Apple's WWDC26 sample uses. https://developer.apple.com/videos/play/wwdc2026/216/
- App Groups: entitlement `com.apple.security.application-groups`; container ID must start with `group.` (e.g. `group.com.example.mygroup`); on macOS you may also use `<TeamID>.<name>` so macOS checks the team ID in the code signature; share via `UserDefaults(suiteName:)` and `FileManager.containerURL(forSecurityApplicationGroupIdentifier:)`; groups must be registered in your developer account (max 1,000). https://developer.apple.com/documentation/xcode/configuring-app-groups
- Since Safari 17 each Safari profile gets its own extension instance (own UUID, background page, storage); native messages carry `SFExtensionProfileKey`; per-site permissions are shared across profiles. https://developer.apple.com/videos/play/wwdc2023/10119/
- Safari 16+: enabling the extension on one device syncs to the user's other devices; automatic when the extension uses the same bundle identifier on macOS and iOS (the Xcode default); otherwise add `SFSafariCorrespondingIOSAppBundleIdentifier`, `SFSafariCorrespondingIOSExtensionBundleIdentifier`, `SFSafariCorrespondingMacOSAppBundleIdentifier`, `SFSafariCorrespondingMacOSExtensionBundleIdentifier` to the respective Info.plists. https://developer.apple.com/documentation/safariservices/syncing-safari-web-extensions-across-devices-and-platforms

## 2. Manifest versions and API support

- MV2 and MV3: "Safari 15.4 and later supports manifest versions 2 and 3". https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility ; MV3 extensions "work in Safari 15.4 and onwards", MV2 continues to be supported. https://developer.apple.com/videos/play/wwdc2022/10099/ ; "Safari 17 will continue to support both Manifest v2 and v3". https://developer.apple.com/videos/play/wwdc2023/10119/ ; MDN: `manifest_version` 2 = Safari 14 / iOS 15, 3 = Safari 15.4 / iOS 15.4, no removal recorded for v2 (BCD 8.1.8). No Apple MV2 end-of-life announcement found (unverified).
- Safari 15.4 (iOS 15.4, macOS 12.3 + Big Sur/Catalina) added MV3, `service_worker` background scripts, `browser.scripting`, DNR dynamic/session rules, `externally_connectable:matches`. https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/
- Background: Safari supports both a background page and a service worker and "both can do the same things"; Apple's sample picks a page because it has DOM access. https://developer.apple.com/videos/play/wwdc2026/216/ ; in MV3 the page must be non-persistent or you declare `"background": {"service_worker": "background.js"}`; Apple recommends the service worker "for better compatibility with other browsers"; on iOS the background page must be non-persistent; in a non-persistent background register listeners at top level, persist state with Storage, use Alarms instead of `setTimeout`. https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari ; BCD: `background.service_worker` 15.4/15.4, `background.persistent` macOS 14.1 (MV2 only), iOS 15.4 partial ("Only non-persistent pages ... Requires persistent: false or service_worker"), `background.type` ("module") 16.4, `background.preferred_environment` 18. https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Browser_compatibility_for_manifest.json
- `scripting`: 15.4/15.4 (usable in MV2 too); `registerContentScripts/getRegisteredContentScripts/unregister/update` 16.4; `executeScript.injectImmediately` not supported; `insertCSS/removeCSS` `origin`, `allFrames`, `frameIds` not supported; `tabs.executeScript` is MV2-only. https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility , https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Browser_support_for_JavaScript_APIs
- `declarativeNetRequest`: API/permission Safari 15 / iOS 15; `updateDynamicRules`/`updateSessionRules` 15.4; `declarativeNetRequestWithHostAccess` 16 (required for `redirect` and `modifyHeaders`, which also need per-site permission); `modifyHeaders` 16.4; up to 50 static rulesets declared, 10 enabled at once; `setExtensionActionOptions({displayActionCountAsBadgeText})` is the only option. https://webkit.org/blog/13966/webkit-features-in-safari-16-4/ , https://developer.apple.com/videos/play/wwdc2022/10099/ , https://developer.apple.com/videos/play/wwdc2023/10119/ , BCD. Blocking needs no page access; redirecting does. https://developer.apple.com/videos/play/wwdc2026/216/
- `storage`: `local` 14/15 with a 5 MB limit; `unlimitedStorage` → 10 MB in Safari ≤15, unlimited in 16+ (users can clear it); `storage.sync` exists but does not sync (acts like `local`; Safari 15/15.1 wrongly stored sync items in `local`); `storage.session` 16.4 (in-memory, cleared on quit, good for secrets); `getKeys()` 18.4. https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility , BCD, https://webkit.org/blog/16574/webkit-features-in-safari-18-4/
- `webRequest`: Apple: "Not supported on iOS"; on macOS no `BlockingResponse`/blocking, `webRequestBlocking` unsupported, `opt_extraInfoSpec` unsupported, and Apple says to keep the macOS background page persistent when using it (impossible in MV3). https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility , https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari ; BCD disagrees for iOS: `webRequest` 18/18 with `onBeforeRequest` 18.4, permission `webRequest` macOS 14 / iOS 18 — treat iOS webRequest as "observe-only, Safari 18+ per MDN, not per Apple" (conflict, unverified which is current).
- `tabs`: 14/15; the `tabs` permission requires host permission; `tabs.move`, `tabs.highlighted`, zoom APIs unsupported; `tabs.query`, `tabs.sendMessage`, `tabs.onUpdated` 14/15. Apple page + BCD (links above).
- `webNavigation`: 14/15 but `onHistoryStateUpdated`, `onCreatedNavigationTarget`, `onReferenceFragmentUpdated`, `onTabReplaced`, `transitionType/Qualifiers` are not supported. Apple page + BCD.
- `alarms` 14/15; `i18n` 14/15 (named-placeholder bugs in `getMessage` fixed in Safari 27); `permissions` 14/15; `cookies` 14/15 (`onChanged` unsupported); `runtime.sendNativeMessage/connectNative` 14/15; `runtime.getBrowserInfo` not supported; `runtime.getDocumentId` 27; `dom.openOrClosedShadowRoot` 26. BCD, https://webkit.org/blog/17967/news-from-wwdc26-webkit-in-safari-27-beta/ , https://webkit.org/blog/18325/webkit-features-for-safari-27-0/
- `contextMenus`/`menus`: macOS 14, iOS not supported. Apple page + BCD.
- `commands`: API 14/15; iOS "Changing the keyboard shortcut for a command is not supported" (BCD); Safari 26 shows commands in the menubar on macOS and iPadOS and lets macOS users customize shortcuts in Safari Settings. https://webkit.org/blog/17333/webkit-features-in-safari-26-0/ (BCD lists the manifest `commands` key as Safari 26 on desktop while the API entries say 14 — discrepancy, unverified.)
- `action` (MV3) 15.4; `browser_action` MV2 only; `action.openPopup` 16; `setBadgeText`/`setIcon` 15.4; grayscale `default_icon` treated as a template (tinted) icon 16.4; single SVG icons 16.4 (`icons.svg_icons`). BCD, https://webkit.org/blog/13966/webkit-features-in-safari-16-4/
- `options_ui` 14/15 but "Options pages are always opened in a separate browser tab"; `options_page` 14/15. BCD.
- `content_scripts`: `world` 18, `css_origin` 18, `match_about_blank`/`match_origin_as_fallback` 18.4, `exclude_globs`/`include_globs` unsupported; "Content scripts are not applied to tabs until the user grants permission" and `run_at` is only honored on loads after the grant. BCD, https://webkit.org/blog/16574/webkit-features-in-safari-18-4/
- Not supported at all (BCD): `notifications`, `bookmarks`, `history`, `downloads`, `management`, `sidebarAction`, `sidePanel`, `userScripts`, `identity` (start OAuth in a tab instead, Apple page), `devtools` on iOS (`devtools_page` macOS 16 only), `update_url` (updates go through the App Store), `externally_connectable.ids` (only `matches`, 15.4), `content_security_policy.sandbox`, file: URL permissions (ignored). Apple page + BCD.
- Safari supports both `browser.*` and `chrome.*` namespaces, callbacks and Promises. https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility
- iOS-only gaps summary: `windows.create/remove/update`, `contextMenus`/`menus`, `webRequest` (per Apple), `devtools`, shortcut customization, app→JS native messaging, persistent background pages. Sources above + https://developer.apple.com/videos/play/wwdc2021/10104/

## 3. Safari permission model

- Declare `permissions` (API permissions, `activeTab`, `<all_urls>`), `host_permissions` (MV3 host patterns), `optional_permissions`, and `content_scripts.matches`; request the least access; prefer `activeTab`, host permissions and optional permissions; `<all_urls>` only if unavoidable. https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions
- Runtime behaviour: when the extension lacks access to the current page Safari badges its toolbar item; on macOS the user clicks it and grants "for a single use", "for the day", or "for all websites", or denies; per-site states are Ask/Allow/Deny; on iOS the user picks the extension in the More menu; Safari 17+: a grant applies across all profiles, private browsing and non-profile browsing. Same URL. The dialog wording Apple shows: "Allow for One Day, or Always Allow"; after a grant the toolbar icon is tinted. https://developer.apple.com/videos/play/wwdc2023/10119/ , https://developer.apple.com/videos/play/wwdc2026/216/ ; the iOS tester tapped "Allow For One Day". https://developer.apple.com/videos/play/tech-talks/110148/
- iOS: if scripts call privacy-sensitive APIs without permission "Safari will wait to call your completion handlers and will show a non-disruptive banner at the top of the screen"; users have "about a minute to respond". https://developer.apple.com/videos/play/wwdc2021/10104/ , https://developer.apple.com/videos/play/tech-talks/110148/
- `activeTab`: access only to "the current website in just the current tab", revoked on navigation, no prompt shown. https://developer.apple.com/videos/play/wwdc2021/10104/
- `browser.permissions.request()` 14/15: requesting `<all_urls>`/`*://*/*` lets the extension prompt for any visited site via the popover/banner; API permissions are granted without prompting, only specific origin patterns prompt. BCD (`permissions.request` notes). `optional_host_permissions` 15.5 (BCD). Sample: `browser.permissions.request({origins: ["*://host/*", "*://*.host/*"]})`. https://developer.apple.com/videos/play/wwdc2026/216/
- Where users enable it — macOS: Safari > Settings > Extensions (checkbox), per-site via the extension's Websites tab. https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions , https://support.apple.com/guide/safari/use-safari-extensions-sfri32508/mac — iOS 27: Settings > Apps > Safari > Extensions > (extension) > "Allow Extension"; per-site: in Safari tap the Page Menu button > "Manage Extensions"; extensions also listed under the More menu > Extensions. https://support.apple.com/guide/iphone/get-extensions-iphab0432bf6/ios , https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension
- Safari 17+: extensions that inject scripts/read pages are off in Private Browsing by default (user toggle). https://developer.apple.com/videos/play/wwdc2023/10119/
- Match patterns: `*://*.youtube.com/*` matches `youtube.com` and every subdomain (`www.`, `m.`, `music.`, …); `*://youtube.com/*` matches only the bare host; the host wildcard may only lead; path matching includes the query string. https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Match_patterns — Apple refers to the same page. https://developer.apple.com/documentation/safariservices/troubleshooting-your-safari-web-extension
- `youtube-nocookie.com` is YouTube's privacy-enhanced embed domain (`https://www.youtube-nocookie.com/embed/...`), standard embeds use `https://www.youtube.com/embed/...`. https://support.google.com/youtube/answer/171780 — Google lists `*.googlevideo.com`, `*.ytimg.com`, `*.youtube-nocookie.com` as additional YouTube-related hosts. https://support.google.com/a/answer/9012184 . So one grant for `youtube.com` does not cover `youtube-nocookie.com` or `googlevideo.com`: they are separate hosts in match patterns (MDN rules above). Whether Safari's per-site grant is keyed on the top-level page or the frame's host when your script runs inside an embed on a third-party page: not documented in the sources consulted (unverified). Safari grants cover the whole domain ("it didn't prompt for extra permission because it's part of the apple.com domain"). https://developer.apple.com/videos/play/tech-talks/110148/
- App Review: "Safari extensions should not claim access to more websites than strictly necessary to function." (4.4.2) https://developer.apple.com/app-store/review/guidelines/

## 4. iOS specifics

- Minimum: iOS 15 (web extensions "coming to iOS 15"; Xcode 13 converter added iOS). https://developer.apple.com/documentation/safariservices/safari-web-extensions , https://developer.apple.com/videos/play/wwdc2021/10104/
- iPhone gets the mobile site: "Google Search results about YouTube from iPhones/iPods direct to m.youtube.com" while "from iPads direct to youtube.com"; youtube.com/m.youtube.com/youtu.be links open the YouTube app via Universal Links on iOS 9+. https://support.google.com/youtube/answer/7174035 ; "You can use YouTube for Mobile Web or Desktop mode on your phone", no editing/uploading on mobile browsers. https://support.google.com/youtube/answer/3008060
- iPad: since iPadOS 13 "iPad will now present itself to websites as a Mac" (desktop-class browsing); narrow windows/iPad mini may get mobile sites; Safari picks a mode automatically. https://developer.apple.com/videos/play/wwdc2019/203/ ; "On iPad, Safari shows a website's desktop version that's automatically scaled for the iPad display"; the page menu offers "Request Mobile Website (if available)". https://support.apple.com/guide/ipad/browse-the-web-ipad999d68f9/14.0/ipados/14.0 ; the iPadOS 27 guide still lists "Request Desktop Website (if available)". https://support.apple.com/guide/ipad/customize-your-safari-settings-ipad54f3cde6/ipados
- iPhone "Request Desktop Website": Page Menu button > "Request Desktop Website (if available)" (iOS 27 guide). https://support.apple.com/guide/iphone/customize-your-safari-settings-iphb3100d149/ios . Whether YouTube then serves the desktop `www.youtube.com` DOM on iPhone: not documented by Google (unverified) — test both `m.youtube.com` and desktop DOMs.
- Popup: "on iPhone, Safari will display this web page as a sheet", full width, "may be laid out taller than the content expects", same in landscape; iPad and Mac use a popover; put the background on `body`, add padding, test Dynamic Type sizes. https://developer.apple.com/videos/play/wwdc2021/10104/ ; on iOS the user opens the extension from the Aa/page menu. https://developer.apple.com/videos/play/tech-talks/110148/
- Background on iOS: "Extensions on iOS must have a non-persistent background page" (`"persistent": false` or a service worker); Safari unloads it when the user is not interacting, so keep state in `storage` and use `alarms`. https://developer.apple.com/videos/play/wwdc2021/10104/ , https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari
- Windows on iOS: window placement is user-controlled; each Safari scene reports two windows (regular + private), Split View doubles that; `windows.onRemoved` may not fire. https://developer.apple.com/videos/play/wwdc2021/10104/
- Input: use Pointer Events, not mouse events; make pages responsive; support Dynamic Type; feature-detect APIs (`typeof browser.contextMenus !== "undefined"`). https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari
- iPadOS extras: commands appear in the menubar (Safari 26). https://webkit.org/blog/17333/webkit-features-in-safari-26-0/ ; the iOS app and extension also run as a compatible app on Apple Vision Pro. https://developer.apple.com/documentation/safariservices/packaging-and-distributing-safari-web-extensions-with-app-store-connect
- Debug builds: extension details in Settings "will only appear in Settings for debug builds of your app from Xcode and not for copies from the App Store or TestFlight". https://developer.apple.com/videos/play/wwdc2021/10104/
- Containing iOS app cannot push messages to the extension JS; content scripts cannot call `sendNativeMessage`. https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension

## 5. Building and running headlessly (no Xcode GUI)

- `DEVELOPER_DIR` "Overrides the active developer directory" set by `xcode-select`; use it for one shell without sudo: `env DEVELOPER_DIR=/Applications/Xcode.app /usr/bin/xcodebuild ...` (man xcode-select, man xcrun, local). Background: https://developer.apple.com/library/archive/technotes/tn2339/_index.html . On this machine `xcode-select -p` is the CLT path, so without `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` `xcodebuild` errors "requires Xcode" (local). Alternative: `sudo xcode-select -s /Applications/Xcode.app`.
- Generate/inspect: `xcodebuild -list -project App.xcodeproj` (targets, configs, schemes); `-showsdks`; `-showdestinations -scheme "App (iOS)"`; `-showBuildSettings`. https://developer.apple.com/library/archive/technotes/tn2339/_index.html and `xcodebuild -help` (local).
- Verified commands (local, packager-generated project, Xcode 27.2):
  - macOS: `xcodebuild -project App.xcodeproj -scheme "App (macOS)" -configuration Debug -destination 'platform=macOS,arch=arm64' -derivedDataPath build CODE_SIGNING_ALLOWED=NO build` → `build/Build/Products/Debug/App.app` with `Contents/PlugIns/App Extension.appex`. Apple's samples instead use "Sign to Run Locally" (ad-hoc signing) with Team = None. https://developer.apple.com/documentation/safariservices/building-and-testing-a-safari-web-extension
  - iOS Simulator: pick a UDID from `xcrun simctl list devices available` (on this install the 27.2 runtime has iPhone 18 Pro / iPhone Air / iPad Air (M4); "iPhone 17 Pro" only exists on the 26.5 runtime, so `name=iPhone 17 Pro,OS=27.2` fails), then `xcodebuild -project App.xcodeproj -scheme "App (iOS)" -configuration Debug -destination "platform=iOS Simulator,id=$UDID" -derivedDataPath build CODE_SIGNING_ALLOWED=NO build` → `build/Build/Products/Debug-iphonesimulator/App.app`.
  - `xcrun simctl boot $UDID; xcrun simctl bootstatus $UDID -b; xcrun simctl install $UDID build/Build/Products/Debug-iphonesimulator/App.app; xcrun simctl launch $UDID com.example.app; xcrun simctl openurl $UDID https://m.youtube.com; open -a Simulator` (to see it); `xcrun simctl shutdown $UDID`. Subcommands from `xcrun simctl help` (local). Destination syntax reference: https://developer.apple.com/library/archive/technotes/tn2339/_index.html
- Where products land: default DerivedData (Xcode Locations) or `-derivedDataPath PATH` ("specifies the directory where build products and other derived data will go", `xcodebuild -help`, local); `CONFIGURATION_BUILD_DIR` defaults to `$(BUILD_DIR)/$(CONFIGURATION)`. https://developer.apple.com/documentation/xcode/build-settings-reference
- First run on macOS: "You need to run the containing macOS or iOS app for your extension at least once to install it in Safari" → `open build/Build/Products/Debug/App.app`; verify registration with `pluginkit -mAvvv -p com.apple.Safari.web-extension`. https://developer.apple.com/documentation/safariservices/troubleshooting-your-safari-web-extension
- Unsigned extensions on macOS: Safari > Settings > Advanced > "Show features for web developers" (Safari 17+; "Show Develop menu in menu bar" earlier), then Settings > Developer > "Allow unsigned extensions" (Safari ≤16: Develop > Allow Unsigned Extensions); the setting resets every time Safari quits; then Settings > Extensions > check the extension. https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension
- No-rebuild loop on macOS: Settings > Developer > "Add Temporary Extension…" pointing at the `Shared (Extension)/Resources` folder or a zip; the Extensions tab gets a Temporary list with a Reload button; temporary extensions are removed after 24 hours or when Safari quits. Same URL and https://developer.apple.com/documentation/safariservices/building-and-testing-a-safari-web-extension
- Do JS edits need a rebuild? With the Xcode path yes: "Xcode packages the latest extension files into the iOS app" (Product > Run on iOS; Product > Build on macOS); resources are copied into the `.appex` (local). https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension . Note `--copy-resources` vs referenced resources in the packager. https://developer.apple.com/documentation/safariservices/packaging-a-web-extension-for-safari
- iOS Simulator: unsigned extensions can be tested in the simulators without a paid membership; enable the extension in the simulator's Settings > Safari > Extensions (iOS 27: Settings > Apps > Safari > Extensions) or Safari More menu > Extensions. https://developer.apple.com/documentation/safariservices/distributing-your-safari-web-extension , https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension , https://support.apple.com/guide/iphone/get-extensions-iphab0432bf6/ios

## 7. App Store Review Guidelines and legal points (all guideline quotes from https://developer.apple.com/app-store/review/guidelines/ )

- 4.4: apps "hosting or containing extensions must comply with ... the Safari web extensions documentation and should include some functionality, such as help screens and settings interfaces where possible"; disclose the extensions in marketing text; "the extensions may not include marketing, advertising, or in-app purchases".
- 4.4.2: "Safari extensions must run on the current version of Safari ... They may not interfere with System or Safari UI elements and must never include malicious or misleading content or code ... should not claim access to more websites than strictly necessary to function."
- 4.2 minimum functionality: "Your app should include features, content, and UI that elevate it beyond a repackaged website"; 4.2.3(i) the app must work without another app. The template app only shows on/off state — add real settings/help in the container (4.4) to be safe.
- 2.5.1 public APIs only; 2.5.2 no downloading/executing code that changes functionality (MV3 already forbids remote scripts: "remote sources for scripts are no longer allowed for version 3", https://developer.apple.com/videos/play/wwdc2022/10099/ ); 2.5.4 background services only for intended purposes; 2.5.6 web browsing must use WebKit.
- 3.1.1: unlocking features requires in-app purchase ("subscriptions ... premium content, or unlocking a full version"); no license keys. Combined with 4.4, put any purchase in the containing app, not the extension.
- 4.8: if you use a third-party/social login (e.g. Google Sign-In) for the primary account you must also offer an equivalent privacy-preserving login option (name/email only, hide email, no ad tracking without consent).
- 5.1.1: privacy policy link in ASC metadata and in-app; consent for collected data even if anonymous; data minimization; account deletion if accounts exist.
- Privacy manifest `PrivacyInfo.xcprivacy`: keys `NSPrivacyTracking`, `NSPrivacyTrackingDomains`, `NSPrivacyCollectedDataTypes`, `NSPrivacyAccessedAPITypes`; required-reason APIs must be declared on iOS/iPadOS/tvOS/visionOS/watchOS, data types on all platforms; create via File > New File > App Privacy File. https://developer.apple.com/documentation/bundleresources/privacy-manifest-files ; since May 1 (2024) uploads need approved reasons for listed APIs. https://developer.apple.com/news/?id=3d8a9yyh ; App Privacy "nutrition label" answers are required for every new app/update; on-device-only processing is not "collection". https://developer.apple.com/app-store/app-privacy-details/ . Whether the `.appex` needs its own manifest is not stated (unverified) — Apple's page addresses apps and SDKs.
- 5.2.1: no third-party trademarks without permission, no misleading/copycat names or metadata; 5.2.2: using/displaying a third-party service's content requires being "specifically permitted to do so under the service's terms of use", authorization on request; 5.2.3: no saving/converting/downloading media from "YouTube ... without explicit authorization".
- YouTube brand guidelines: "You must never use the YouTube name or any abbreviation, acronym, or variant of the word YouTube" with your app's name (forbidden examples "YouTube for Kids", "YouTube Education"); you "may reference the fact that your app is for YouTube or works with YouTube" (e.g. "great app for YouTube"); do not modify logo colors or elements, do not make a YouTube mark the most prominent element, do not adopt confusingly similar marks/trade dress including "product icons"; endorsement-implying uses need written permission. https://developers.google.com/youtube/terms/branding-guidelines
- YouTube Terms of Service (dated January 5, 2022): you may not "alter, modify or otherwise use any part of the Service or any Content" except as authorized, nor "circumvent, disable, fraudulently engage with, or otherwise interfere with any part of the Service", nor access it "using any automated means"; the section does not name ad blockers. https://www.youtube.com/t/terms ; YouTube Help: "When you block YouTube ads, you violate YouTube's Terms of Service" and playback may be blocked. https://support.google.com/youtube/answer/14129599
- Apple's position: Safari ships a Content Blocker extension API ("hiding elements, blocking loads, and stripping cookies"; declarative JSON rules compiled to bytecode; blockers have no knowledge of history). https://developer.apple.com/documentation/safariservices/creating-a-content-blocker ; App Review allows extensions (4.4) but 5.2.2 defers to the third party's terms. Both positions stated as-is; no opinion offered.
- Naming: "<Name> for YouTube" is the construction the brand page permits; keep "YouTube" out of the app name itself and the icon free of YouTube trade dress (brand page) and avoid confusingly similar names (5.2.1).

## 9. Localization and accessibility

- Extension: `_locales/<locale>/messages.json` with `{"key": {"message": "...", "description": "..."}}`, `default_locale` in the manifest, `__MSG_key__` in manifest/CSS, `browser.i18n.getMessage("key", substitutions)`; locale folders use underscores (`en_US`); fallback chain region → script → language → default. https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Internationalization ; the Xcode template already uses `__MSG_extension_name__`/`__MSG_extension_description__` with `_locales/en/messages.json` (local); `i18n` is Safari 14 / iOS 15 (BCD).
- Swift app: String Catalogs (`Localizable.xcstrings`) introduced in Xcode 15, superseding `.strings`/`.stringsdict`; Xcode extracts `String(localized:)`, SwiftUI `Text`, `NSLocalizedString`, Interface Builder strings on every build; right-click > "Migrate to String Catalog". https://developer.apple.com/videos/play/wwdc2023/10155/ , https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog ; Xcode 27 adds machine-translation state and a "Generate Translations" button. https://developer.apple.com/documentation/xcode-release-notes/xcode-27-release-notes
- Popup/options HTML accessibility: label controls for VoiceOver/Voice Control, provide a button alternative to gesture dismissal, let text enlarge ≥200%, contrast ≥4.5:1 for text ≤17 pt (3:1 at 18 pt/bold), respect Reduce Motion by reducing automatic/repetitive animation, don't rely on colour alone, 44×44 pt default control size (28×28 minimum). https://developer.apple.com/design/human-interface-guidelines/accessibility
- Dynamic Type in web content: `font: -apple-system-body` (also `-apple-system-headline`, `-subheadline`, `-caption1/2`, `-footnote`, `-short-*`, `-tall-body`) and `font-family: -apple-system`. https://webkit.org/blog/3709/using-the-system-font-in-web-content/ ; Apple: these system fonts "respect the user's text size preference and resize to match"; test popups at several Dynamic Type sizes; support Dynamic Type on iOS. https://developer.apple.com/videos/play/wwdc2021/10104/ , https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari
- Reduced motion: `@media (prefers-reduced-motion: reduce) { ... }` (Safari 10.1 / iOS 10.3 per BCD). https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion ; Dark Mode: `:root { color-scheme: light dark; }`. https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari

## 11. Gotchas

1. `xcode-select` points at Command Line Tools here → every `xcodebuild`/`xcrun simctl` call needs `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (local; man xcode-select).
2. `swift --version` from CLT reports 6.2.3, but Xcode 27.2 builds with Swift 6.4.2; the packager sets `SWIFT_VERSION` 5.0 language mode (local). https://developer.apple.com/support/xcode/
3. Packager gives the iOS app target 17.0 and the iOS extension 15.0; Apple says app and extension deployment targets should match — fix both (local; https://developer.apple.com/documentation/safariservices/troubleshooting-your-safari-web-extension ).
4. Extension bundle ID must be a child of the app's bundle ID (`com.example.App.Extension`); App Store Connect additionally rejects more than one extra period. https://developer.apple.com/forums/thread/101754 , https://developer.apple.com/forums/thread/680350
5. "Allow unsigned extensions" resets each time Safari quits; the containing app must be launched once; check with `pluginkit -mAvvv -p com.apple.Safari.web-extension`. https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension , https://developer.apple.com/documentation/safariservices/troubleshooting-your-safari-web-extension
6. Content scripts do not run until the user grants site access; `run_at` only applies on later loads — your YouTube script must tolerate being injected mid-page. BCD `content_scripts` notes. https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Browser_compatibility_for_manifest.json
7. YouTube is a single-page app and Safari lacks `webNavigation.onHistoryStateUpdated` — detect navigation in the content script (e.g. `MutationObserver`, `popstate`, or the Navigation API `navigate` event, Safari 26.2+ per BCD); YouTube's `yt-navigate-finish` DOM event is community lore, not documented by Google (unverified). https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility
8. `webRequest` cannot block (no `BlockingResponse`), is "not supported on iOS" per Apple, and wants a persistent page on macOS; use `declarativeNetRequest` (needs `declarativeNetRequestWithHostAccess` + site permission for redirect/modifyHeaders). Links in §2.
9. `storage.sync` does not sync (behaves as `local`); `local` is 5 MB unless `unlimitedStorage`; `storage.session` needs Safari 16.4+. §2 links.
10. MV3 CSP: `content_security_policy.extension_pages` object; no remote scripts; `web_accessible_resources` is scoped per `matches`; the extension base URL is always dynamic (`use_dynamic_url` is moot). https://developer.apple.com/videos/play/wwdc2022/10099/ , BCD.
11. Non-persistent background: no long-lived timers (`setTimeout`) — use `alarms`; keep listeners top-level; `windows`/`contextMenus` missing on iOS → feature-detect. https://developer.apple.com/documentation/safariservices/optimizing-your-web-extension-for-safari
12. Popup is a full-width sheet on iPhone, a popover on iPad/Mac: set `body` background, avoid fixed desktop widths (`width: 100px` in the template popup.css). https://developer.apple.com/videos/play/wwdc2021/10104/
13. Icons: extension icons PNG 48/64/96/128/256/512, toolbar 16/19/32/38 (or one SVG, Safari 16.4+); App Store icon 1024×1024 (iOS auto-generates sizes, macOS needs every size or an Icon Composer file); grayscale action icons are auto-tinted. https://developer.apple.com/documentation/safariservices/creating-a-safari-web-extension , https://developer.apple.com/documentation/xcode/configuring-your-app-icon , https://developer.apple.com/design/human-interface-guidelines/app-icons
14. Ignored/unsupported manifest keys: `update_url`, `webRequestBlocking`, `externally_connectable.ids`, file: patterns, `devtools_page` on iOS, `notifications`, `sidebar_action`/`side_panel`, `options_ui.open_in_tab` (always a tab). §2 links.
15. `tabs` permission does not grant page access — host permission is still needed; `activeTab` prompts nothing but dies on navigation. §2–3 links.
16. Each Safari 17+ profile is a separate extension instance with separate storage; Private Browsing is off by default for the extension. https://developer.apple.com/videos/play/wwdc2023/10119/
17. On iOS the app cannot push to the extension and content scripts cannot talk natively — route settings through `storage` or an App Group + `sendNativeMessage` from the background. https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension
18. Before Safari 27.2 there was "a significant delay before web extension content is injected when Safari is cold launched" (fixed in 27.2) — expect late injection on older Safari. https://webkit.org/blog/18515/webkit-features-for-safari-27-2/
19. Simulator destinations: device names are per runtime (the 27.2 runtime here has iPhone 18 Pro, not iPhone 17 Pro) — use `-showdestinations` or a UDID; `xcodebuild -list` defaults to Release when no scheme is passed (local).
20. Review: 4.4 forbids IAP/ads inside the extension; 4.2 wants real app functionality; 5.2.2/5.2.3 tie you to YouTube's terms; don't put "YouTube" in the app name. §7 links.
