# Safari + YouTube platform limits (verified in this project)

| Date | Finding | Evidence | Consequence |
|---|---|---|---|
| 2026-11-03 | Volume booster is impossible in Safari. `AudioContext.createMediaElementSource(video)` connects and reports `state: running`, gain set to 4, source attached, but the audible level does not change. WebKit does not route MSE (Media Source Extensions) audio, which YouTube uses for every stream, through Web Audio. Tested from both the isolated content-script world and the page world (`world: "MAIN"`). | `[ytx] boost {level: 4, result: {level: 4, state: "running", sources: true}}` in the YouTube tab console, Safari 27.2, macOS 27.2, no change in loudness; same result from a hand-written console snippet in the page context. | Feature removed from settings, toolbar and page bridge. Do not reintroduce unless WebKit ships MSE support in `MediaElementAudioSourceNode` (track https://bugs.webkit.org/ for "MediaElementAudioSourceNode MSE"). |
| 2026-11-03 | YouTube's CSP blocks an injected `<script src=safari-web-extension://…>` (`strict-dynamic` + Trusted Types). | Bridge calls timed out until `page.js` became a `world: "MAIN"` content script. | Page-world code must be declared in the manifest, never injected. |
| 2026-11-03 | Ctrl+scroll never reaches the page on macOS Safari; Ctrl+click is the system right-click. | Wheel listener fired for plain and Option scroll only. | Modifier gestures use Option (⌥). |
| 2026-11-03 | After an extension reinstall or update, open YouTube tabs keep the old content script and lose their `storage.onChanged` listener. | New settings "needed a reload" during development. | `background.js` reloads every youtube.com tab on `runtime.onInstalled`. |

## YouTube internals used by the extension (verified from the live bundles, 2026-11-03)

- Full screen on the desktop watch page is requested on `document.documentElement`, not the player: `toggleFullscreen` in base.js takes the `externalFullscreen` branch and calls `ur(window.document.documentElement)`; Shorts and mini-apps do the same. The app then reads `document.fullscreenElement` (`_.xL()`, `Yf()`) on `fullscreenchange` and calls `player.setFauxFullscreen(true)`; no YouTube CSS depends on `:fullscreen`. `winfull.js` therefore spoofs the getters and fires the event instead of restyling elements.
- Captions module (`player_es6.vflset/en_US/captions.js`): `setOption("captions","track", t)` matches `t.languageCode` against the track list (first match wins, manual tracks listed before ASR), and `t.translationLanguage` (an entry of `getOption("captions","translationLanguages")`) makes a translated copy of that track; `tracklist` takes `{ includeAsr: true }`; plain track copies expose `is_translateable`, `vss_id`, `kind` ("asr").
- The 156 translation language codes in `defaults.js` (`LANGS`) come from `translationLanguages` in `ytInitialPlayerResponse`; all resolve in `Intl.DisplayNames`.
- Theme: YouTube serves a different main stylesheet per theme (`/s/_/ytmainappweb/_/ss/...`, selected by the `PREF` cookie `f6=400` for dark) and pins a few colour tokens in it with a `:root:root` rule (specificity above `[dark]`), the Subscribe button text among them. Forcing the `dark` attribute on a page served light therefore leaves that button white on white. Switch themes through YouTube's own action instead: dispatch `yt-action` on `ytd-app` with `actionName: "yt-signal-action-toggle-dark-theme-on" | "-off" | "-device"` (handled by `ytd-app`, which saves the pref and reloads when the theme changes); wait for `yt-navigate-finish` before dispatching.

## YouTube internals verified by curl on 2026-11-04 (desktop HTML, guest, `.atlas/plans/2026-11-04-1045-power-creator-plan.md`)

- `movie_player.getPlayerResponse()` is an exported player method (base.js `UL(a,"getPlayerResponse",a.Za)`), so the current video's response is available after SPA navigation; `ytInitialPlayerResponse` only matches the first video. `page.js` `details` reads: `videoDetails` (videoId, title, author, channelId, lengthSeconds, keywords, viewCount, isLiveContent), `microformat.playerMicroformatRenderer` (publishDate with time zone, category, viewCount, externalChannelId), `captions.playerCaptionsTracklistRenderer.captionTracks[]` (languageCode, kind "asr"), `storyboards.playerStoryboardSpecRenderer.spec`, `adPlacements[].adPlacementRenderer.config.adPlacementConfig` (kind AD_PLACEMENT_KIND_START or _MILLISECONDS, adTimeOffset.offsetStartMilliseconds), `endscreen.endscreenRenderer.elements[].endscreenElementRenderer` (style VIDEO/PLAYLIST/CHANNEL/WEBSITE, title, startMs, endMs, endpoint url), `cards.cardCollectionRenderer.cards[].cardRenderer` (teaser message, cueRanges[0].startCardActiveMs).
- Storyboard spec: `base|w#h#count#rows#cols#intervalMs#name#sigh` per level, e.g. `160#90#108#5#5#2000#M$M#rs$…`; the URL is base with `$L` → level and `$N` → name with `$M` → sprite index, plus `&sigh=`; level 0 (`default`, interval 0) spreads `count` frames over the duration. `storyboardTile()` in defaults.js.
- Caption options are `setOption("captions", name, value)`: `fontSizeIncrement` -2..4 (×0.5 to ×4), `color` and `background` hex (#fff, #ff0, #0f0, #0ff, #00f, #f0f, #f00, #080808), `backgroundOpacity`/`windowOpacity`/`textOpacity` 0..1, `charEdgeStyle` 0 none, 1 raised, 2 depressed, 3 outline, 4 drop shadow, `fontFamily`, `windowColor`. Verified from base.js option tables; live effect pending.
- Heat map ("most replayed"): `.ytp-heat-map-path` `d` in a 1000×100 viewBox, one point per marker at y = 100 − intensity; markers also arrive in `ytInitialData` as `macroMarkersListEntity` (MARKER_TYPE_HEATMAP, intensityScoreNormalized) for the first video only. `heatPeaks()` in defaults.js parses the path.
- Like count: the like button's `accessibilityText` is "like this video along with 19,491,293 other people". Channel header rows read "525M subscribers" and "1K videos" (rounded); tabs are Home, Videos, Shorts, … with `/videos` URLs; the DOM tab is `yt-tab-shape[tab-title]`.
- Feeds carry no AI disclosure: search `videoRenderer.badges` only ever hold 4K, CC, New and product counts; home and search data contain no "synthetic" or "altered" fields (only YouTube's own "AI-generated video summary" expander). Hiding AI videos is a word-boundary keyword heuristic.
- YouTube's `img-src` CSP is report-only, so `blob:` images set from the content script render (thumbnail test card).

## Live testing through safaridriver (verified 2026-11-04, Safari 27.2)

- `safaridriver --enable` was already done on this Mac. `safaridriver -p 4444` plus plain WebDriver HTTP calls (node `fetch`) drive a Safari automation window that **does load the enabled extension**: `document.documentElement.dataset.ytx`, `__ytxWinfull` and the toolbar all appear on youtube.com. Rebuilds through `scripts/run-mac.sh` are picked up by the next page load without re-ticking the extension.
- The automation window has its **own extension storage** (`browser.storage.local.get("settings")` is empty), so test settings never touch the user's. The options page is reachable: click the toolbar ••• then the Settings item, which opens `safari-web-extension://<UUID>/options.html` in a new tab of the automation window; `execute/async` there can call `ytx.save(patch)`. Close that tab afterwards: while it is in front the YouTube tab is `document.hidden`, and YouTube then skips IntersectionObserver work (comments, transcript, captions) and throttles timers.
- The window must also be frontmost on screen (`document.visibilityState === "visible"`); `osascript -e 'tell application "Safari" to activate'` helps, otherwise the user has to click the orange-barred window.
- The automation profile is a signed-out fresh visitor: no captions render (timedtext never loads), the transcript panel shows a spinner forever, guests receive no `adPlacements`, and comments never load a second batch, even without the extension. Verify those by hand in the normal Safari.
- `execute/sync` runs in the page's main world: the player API (`movie_player.getPlayerResponse()`), `ytInitialData` and our MAIN-world globals are visible; the isolated-world `ytx` is not. Clicking our toolbar buttons and menu items from there works because DOM events cross worlds.
- The DOM scanner in content.js is a 300 ms throttle, not a debounce: a busy live chat mutates more often than 300 ms and a debounce never fired (emoji-only lines stayed visible until the change).
